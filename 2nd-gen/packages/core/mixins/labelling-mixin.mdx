## Usage

`LabellingMixin` adds visible-label rendering and accessible-name wiring to a host so components do not hand-roll it. It is one of two decoupled primitives for form-field labelling:

- **`LabellingMixin`** (`@adobe/spectrum-wc-core/mixins`): the `accessible-label` / `accessible-labelledby` properties, `label` slot presence tracking, the "no accessible name" dev warning, and `renderLabel()`.
- **`renderFieldLabel`** (`@adobe/spectrum-wc-core/directives/render-label`): the underlying render-only directive. The mixin owns and exposes it; use it directly only for stateless label rendering without the mixin.

`HelpTextMixin` (`@adobe/spectrum-wc-core/mixins`) is the companion mixin for description/error-text association; `swc-text-field` composes both.

### What it does

- **Accessible name**: each source is wired independently, and the browser's [accessible-name computation](https://www.w3.org/TR/accname-1.2/) picks which one is announced, in this order:
  1. **`accessibleLabelledby`** (highest): resolved against the host's root node, written to the role element's `ariaLabelledByElements`.
  2. **`accessibleLabel`**: written to the role element's `aria-label` attribute.
  3. **A slotted visible label** (lowest): rendered as a real, same-root `<label for>`.
- **Label rendering**: `renderLabel()` renders nothing when there is no slotted `label` content, and otherwise always renders a real `<label for>`, so a visible label keeps native click-to-focus even when a programmatic name is announced instead.
- **Dev-mode warnings**: warns when no accessible-name source is set, and separately warns when both `accessibleLabelledby` and `accessibleLabel` are set (the lower-precedence one is ignored).

### Basic usage

1. Apply the mixin to your base class: `class MyField extends LabellingMixin(SpectrumElement) {}`.
2. Override `roleElement` to return the element the accessible name should be wired onto (usually the rendered `<input>` or other native control).
3. Call `renderLabel(inputId)` in your template, passing the `id` of that role element.

```typescript
import { html, LitElement } from 'lit';
import { LabellingMixin } from '@adobe/spectrum-wc-core/mixins';

class MyField extends LabellingMixin(LitElement) {
  override get roleElement() {
    return this.renderRoot.querySelector('input');
  }

  render() {
    return html`
      ${this.renderLabel('my-field-input')}
      <input id="my-field-input" />
    `;
  }
}
```

## Behaviors

### Name source precedence

When more than one source is set, the browser's [accessible-name computation](https://www.w3.org/TR/accname-1.2/) decides which one is announced, in this order:

1. **`accessible-labelledby`** (highest precedence): wins over both `accessible-label` and a slotted label.
2. **`accessible-label`**: wins over a slotted label.
3. **A slotted `label`** (lowest precedence): used when neither of the above is set.

The mixin wires each source independently; it does not enforce this order itself, because the browser already applies it when computing the accessible name. A slotted visible label always renders as a real `<label for>`, so it keeps native click-to-focus even when a higher-precedence source provides the announced name.

### Conflicting label sources

Setting both `accessible-labelledby` and `accessible-label` triggers a dev-mode console warning: they are two ways to give the same field a name, so one is always ignored. The warning names `accessible-labelledby` as the source that is used. Pairing a visible slotted label with either one does not warn; that is the recommended way to satisfy [Label in Name (2.5.3)](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html), where the announced name contains the visible text. Open the browser console to see the warning for the example below.

## Accessibility

### Features

- **Browser-resolved name**: each source (`ariaLabelledByElements`, `aria-label`, a same-root `<label for>`) is wired independently, and the browser's accessible-name computation picks the one that is announced.
- **Native click-to-focus**: a slotted visible label always renders as a real `<label for>`, so clicking the label focuses the field natively, even when a programmatic name is announced.
- **Dev-mode warnings**: a console warning fires for a field with no accessible-name source, for a field that sets both `accessible-labelledby` and `accessible-label`, and for an `accessible-labelledby` that references an `id` matching no element in the field's root.

> **Known axe-core false positive.** A field named only via a resolved `accessible-labelledby` fails automated axe-core scans with a "Form element does not have a label" (`label` rule) violation, even though the name resolves correctly in real browsers and assistive technology. axe-core inspects DOM attributes and has no standardized way to read `ariaLabelledByElements`, the ARIA element-reflection API this mixin uses. Exclude the specific host from the `label` rule with a written `// reason:` comment (see the forms-strategy RFC's axe-core policy, CONTRIBUTOR-DOCS "3.4 axe-core policy") rather than disabling the rule globally; verify the name with manual AT testing instead.

> ⚠️ **Important:** `accessible-labelledby` depends on the ARIA element-reflection API (`ariaLabelledByElements`), which Firefox does not yet support (as of Firefox 143). In an engine without it, assigning the reflected elements is a silent no-op, so a field named only via `accessible-labelledby` has no accessible name there. A same-root `aria-labelledby` IDREF string cannot substitute, because the referenced ids resolve against the host's root while the name is wired onto the control inside the shadow root. For fields that must be named in all engines today, prefer a slotted visible label or `accessible-label`.

### Best practices

- Prefer a slotted label for ordinary fields. Reserve `accessible-label` and `accessible-labelledby` for fields with no visible label of their own, or a name composed from elements the field doesn't own (for example, a grid cell named by its row and column headers).
- When a field has both a visible label and a programmatic name, make sure the programmatic name contains the visible text, per [Label in Name (2.5.3)](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html). Do not set both `accessible-label` and `accessible-labelledby`; a dev-mode warning flags that combination.
- `accessible-labelledby` `id`s are resolved against the field's root node (the document or shadow root that contains it) once per render, so the referenced elements must already exist when the field renders. An element inserted afterward is not picked up until the next render; reassign `accessible-labelledby` after inserting it to force a re-resolution.

## API

### Constructor

`LabellingMixin(BaseClass)` returns `BaseClass` extended with the labelling API.

### Members

| Member                 | Description                                                                                         |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| `accessibleLabel`      | Accessible name, applied as `aria-label`. Lowest precedence after `accessibleLabelledby`.           |
| `accessibleLabelledby` | Space-separated element `id`s that provide the accessible name. Highest precedence.                 |
| `hasLabelSlotContent`  | Read-only. Whether slotted `label` content is present.                                              |
| `roleElement`          | `@internal`. The element the resolved name is wired onto. Override to return the real role element. |
| `renderLabel(forId)`   | Renders the label markup for the current state (via the `renderFieldLabel` directive).              |

### Related primitives

| Export             | Module                                            | Purpose                                                           |
| ------------------ | ------------------------------------------------- | ----------------------------------------------------------------- |
| `renderFieldLabel` | `@adobe/spectrum-wc-core/directives/render-label` | Underlying label render; exposed via the mixin's `renderLabel()`. |
| `HelpTextMixin`    | `@adobe/spectrum-wc-core/mixins`                  | Companion mixin for description/error-text association.           |
