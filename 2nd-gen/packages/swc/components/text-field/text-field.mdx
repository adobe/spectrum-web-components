## Anatomy

A text field consists of:

- **Input**: the real, focusable `<input>` that carries the value and native `textbox` role
- **Label** (optional), provided through the `label` slot: visible text rendered as a real, same-root `<label for>`

## Options

### Labelling

Three sources can provide the field's accessible name. Only the highest-precedence source that is set becomes the accessible name — a lower-precedence source with different text does not get silently combined into it, avoiding a [Label in Name (2.5.3)](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html) mismatch:

1. **`accessible-labelledby`** (highest precedence): space-separated element `id`s, resolved against the field's root node, for composing a name from elements the field does not own (for example, a grid cell named by its row and column headers).
2. **`accessible-label`**: a string accessible name for a field with no visible label of its own.
3. **A slotted `label`** (lowest precedence): the default, recommended path for an ordinary standalone field. Renders as a real, same-root `<label for>`, giving native click-to-focus.

## States

Text fields can exist in various states:

- **Default**: normal, editable state
- **Required**: the native `required` attribute is reflected onto the input; no separate `aria-required` is set
- **Read-only**: focusable and selectable, but not editable; distinct from disabled
- **Disabled**: not editable and removed from the tab order

## Behaviors

### Conflicting label sources

Setting more than one of `accessible-labelledby`, `accessible-label`, and a slotted `label` at once triggers a dev-mode console warning, regardless of which combination it is (two sources, or all three). Only the highest-precedence source present is ever read as the accessible name; the rest are silently ignored. The warning message names both the winning source and the source(s) that will not be read. Open the browser console to see the warning for the examples below.

## Accessibility

### Features

- **Native role** — the host sets no ARIA role; the real `<input>` supplies the implicit `textbox` role.
- **One accessible-name writer** — `accessible-labelledby` &gt; `accessible-label` &gt; slotted label, in that order; exactly one source is wired at a time.
- **Dev-mode warnings** — a field with no visible label, no `accessible-label`, and no `accessible-labelledby` triggers a console warning; so does a field that sets more than one of `accessible-labelledby`, `accessible-label`, and a slotted label, naming which source wins and which will not be read.

### Best practices

- Prefer a slotted `label` for ordinary fields; reserve `accessible-label`/`accessible-labelledby` for fields with no visible label of their own or a name composed from elements the field doesn't own.
- Set only one of `accessible-labelledby`, `accessible-label`, and a slotted label — combining any two (or all three) with different text is enforced with a dev-mode warning, not just documented guidance.
