One source for AI configuration, native to every Copilot surface

.ai/ is the single, tool-agnostic source for this repository's AI rules, skills, and lessons. This page explains how it's exposed to GitHub Copilot (CLI, the GitHub Copilot app, and VS Code), with Claude Code and Cursor served by thin adapters.

Status: approved and in implementation as a stack of pull requests: #6785 (instructions pipeline), #6786 (split rules and memory), #6787 (skills and conventions), the README and this page, and a final community-resources PR that's gated on Adobe open-source review (D-19). Evidence comes from GitHub and VS Code documentation plus live checks on Copilot CLI 1.0.88, VS Code 1.138.0, and the GitHub Copilot app.

§1 Overview

Copilot reads almost none of .ai/ today. The fix keeps .ai/ as the only editable source and exposes it through the paths each Copilot surface already discovers.

The problem

  • Path-scoped rules only reach the VS Code local agent. The CLI, the app, the cloud agent, and code review never see them.
  • Rule frontmatter says the same thing three ways ( globs , paths , alwaysApply ), and two rules contradict themselves.
  • Five skills have loader risks (mismatched names or nesting), and two carry unsupported keys.
  • .ai/README.md hand-duplicates frontmatter and has already drifted.
  • .ai/config.json has no consumer and contradicts the formatter config.
  • Branch naming has four conflicting patterns.

The solution

  • .ai/ stays the only place anyone edits.
  • Native discovery paths are used wherever they already work: AGENTS.md and .claude/skills .
  • Real files are generated only where the format changes or a GitHub.com surface reads them: .github/instructions/ and .cursor/rules/ .
  • yarn lint:ai validates the Copilot targets and fails on drift.
  • The migration follows Adobe's order: instructions, skills and legacy commands, MCP, permissions, agents, hooks, then CI.
  • After the migration, a final PR vendors 11 reviewed community resources from awesome-copilot and superpowers, plus 1 rule derived from them, with attribution. It also lists 36 optional personal installs. Nothing is enforced team-wide.
  • 104 existing files mapped, one row each
  • 1,099 community resources evaluated
  • 12 generated Copilot instruction files after PR 6
  • 42 skills after PR 6, one level deep
  • 16 yarn lint:ai checks
  • 25 decisions, all accepted

§3 Structure

Typed folders, one frontmatter schema per type. Everything under .ai/ is edited by hand. Everything on the right is derived.

.gitattributes marks the generated instruction and Cursor rule files as linguist-generated=true , so GitHub collapses them in pull request diffs.

§4 Formats

Canonical keys reuse spellings that at least one tool already documents. Nothing new is invented.

Instruction: .ai/rules/<name>.md and .ai/memory/<name>.md

paths is required. Anything that should always apply goes in AGENTS.md , because applyTo only fires when a matching file is involved, and Copilot defines no precedence between instruction files. The validator rejects globs , alwaysApply , applyTo , and name .

Prompt (reserved)

Prompt files are only loaded by the VS Code local agent. They're deprecated for Agent Host and unsupported by the CLI and GitHub.com (E11, E21). Author a skill instead. §5 Pipeline

A hybrid: native paths where they work, generated files where a format has to change, symlinks where the format is identical, and one workspace setting for VS Code local.

Diagram in words
  • .ai/rules/*.md and .ai/memory/*.md go through sync.js , which writes .github/instructions/*.instructions.md for Copilot and .cursor/rules/*.mdc for Cursor.
  • sync.js also reads skill frontmatter and writes the catalog block in .ai/README.md .
  • .claude/rules links to .ai/rules for Claude Code, because the canonical paths key is Claude's own key.
  • .claude/skills links to .ai/skills . It's the single skills path for Copilot and Claude Code. .cursor/skills does the same for Cursor.
  • AGENTS.md files are authored and read in place.
  • yarn lint:ai validates every target and fails when a generated file doesn't match its source.

Generator behavior

  • yarn ai:sync runs node .ai/scripts/sync.js and writes the targets. --check writes nothing and exits 1 with a diff summary on drift.
  • It parses YAML with the yaml package, formats output with the repository's Prettier config, normalizes to LF line endings, and deletes orphaned generated files, which it identifies by their generated header.
  • The husky pre-commit hook runs yarn ai:sync and stages the outputs when files under .ai/ or AGENTS.md files are staged (D-16).

All four keys are listed explicitly, so the result is the same whether VS Code merges this object with its defaults or replaces them. These settings only affect the VS Code local agent.

§7 Migration map

Every Claude-era and .ai/ file gets exactly one verdict.

Verdicts follow Adobe's migration agent (A3): KEEP (no change), ADAPT (stays in place; behavior or metadata changes), CONVERT (new format or location), CONFIGURE (expressed as a setting), and REMOVE . Following A3, renaming a skill directory to match its name counts as ADAPT, because it's metadata normalization. Moving a file to a different parent folder counts as CONVERT.

§8 Authoring

Edit .ai/ , run the sync, and let yarn lint:ai tell you what's wrong. Never edit a file with the generated header. The yarn ai:sync command and the new checks arrive with PR 1.

Add a path-scoped instruction

  1. Create .ai/rules/<name>.md with description , a quoted paths list, and excludeAgent only if code review or the cloud agent shouldn't see it.
  2. If the guidance should always apply, add a line to AGENTS.md instead.
  3. Run yarn ai:sync , then commit the source and the generated files together.
  4. Run yarn lint:ai . It fails if a glob matches no tracked file.

Add a skill

  1. Create .ai/skills/<name>/SKILL.md . The directory name must equal name .
  2. Write a description that says what the skill does and when to use it, in 1,024 characters or fewer.
  3. Put supporting files in the skill's references/ , assets/ , or scripts/ folder and link them from SKILL.md . Never pre-approve shell or bash .
  4. Run yarn ai:sync to refresh the README catalog, then yarn lint:ai .
  5. Confirm it loads with copilot skill list --json .

Add a lesson or an agent

  1. Lessons go in .ai/memory/<topic>-lessons.md with the instruction frontmatter. The session-retrospective skill writes them.
  2. New agents need a decision first, because a skill is the default. Then add .ai/agents/<name>.agent.md using the schema in §4. It's generated to .github/agents/ , and the agents pipeline arrives in PR 6.
  3. Vendored community content carries license and metadata.source , source-path , and source-sha . Check 15 fails without them.

Verify on each surface

  • Copilot CLI: copilot instruction list and copilot skill list --json , run from the repository root or a subdirectory.
  • VS Code: run Chat: Open Customizations with the Copilot harness selected, then check Instructions and Skills .
  • Copilot app: Customize , then Skills .
  • Windows without symlinks: run copilot skill add <repo>/.ai/skills once to add the skills directory for the CLI.
