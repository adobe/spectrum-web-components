## F. Gaps vs. React Spectrum AI

Details and verdicts are in [`05-react-spectrum-comparison.md`](./05-react-spectrum-comparison.md). These items are listed here so they get tracked.

| #   | Sev | Where                                       | Problem                                                                                                                                                                                                 | Fix                                                                                                                                                                                                                              |
| --- | --- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 33  | 🟠  | `response-status/ResponseStatus.ts:54`      | Statuses are `active \| complete \| stopped`. There's no `failed`, and no in-thread error element. React Spectrum has `failed` plus `Alert`. Products have no supported way to show a generation error. | Add a `failed` status. Track an error affordance alongside the gen2 alert work (there's only a core `alert-banner` base today, no `swc` alert). Until then, document the expected error copy pattern in the system-message body. |
| 34  | 🟡  | `message-feedback/MessageFeedback.ts:38-47` | Controlled only, and there's no way to clear a selection (toggle off). React Spectrum supports controlled + uncontrolled, and toggling off to `null`.                                                   | Fold into the #10 convention: self-update, cancelable change event, clicking again clears.                                                                                                                                       |
| 35  | 🟡  | `conversation-thread`                       | No scroll pinning while streaming, no scroll-to-latest affordance, no load-older hook. Every consumer re-implements these. React Spectrum builds all three in.                                          | Start with a documented recipe in the full-pattern story. Decide on a built-in after there's product demand.                                                                                                                     |

React Spectrum precedent also strengthens three existing items:

- **#10**: React applies one controlled/uncontrolled rule to every stateful piece. That's evidence the "one convention" fix is achievable.
- **#11**: React uses `pending \| success \| failed`. Any SWC vocabulary change should align with it, not invent a third set.
- **#17**: React composes sources from child list items instead of reading slotted anchors, which removes the read-once problem by design.

## Not issues (checked and fine)

- Pattern elements extending `SpectrumElement` without a core Base: this is an intentional, documented exception.
- Every element has `@element` + `@since` JSDoc.
- Event prefixes are `swc-` everywhere. All events bubble and are composed (one agent reported otherwise; the code confirms they bubble).
- `yarn lint:docs-pages` passes. That's partly because pattern pages are exempt from sentence-case checks (`scripts/validate-docs-pages.js:32-33`) and `pattern-overview.mdx` is skipped entirely (`:149`).
