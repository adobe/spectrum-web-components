**feat(core, text-field):** Added `LabellingMixin`, a Lit mixin that owns visible-label rendering and precedence-ordered accessible-name wiring for form fields, replacing the never-built `LabellingController` from the forms-strategy RFC.

- **`@adobe/spectrum-wc-core`**: adds `LabellingMixin` (`/mixins`), which wires up to three accessible-name sources: `accessibleLabelledby` (resolved against the host's root node, written to the role element's `ariaLabelledByElements`), `accessibleLabel` (written to `aria-label`), and a slotted visible label (always rendered as a real, same-root `<label for>` so it stays clickable). Each source is wired independently; when more than one is set, the browser's accessible-name computation decides which is announced. The mixin warns in development builds when no accessible-name source resolves to anything; when a field is named only by its `placeholder` (an unreliable accessible name); when `accessibleLabelledby` references an id that resolves to no element; when both `accessibleLabelledby` and `accessibleLabel` are set (two competing programmatic names, of which `accessibleLabelledby` wins); and when `aria-label`/`aria-labelledby` is set on the host itself, where it does not name the field. A visible label paired with `accessibleLabel` is the recommended [WCAG 2.5.3 (Label in Name)](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html) pattern and does not warn. A `placeholderText` override lets a host expose its placeholder to the warning, and a `labelInternals` override lets a control with no inner role element (e.g. a future radio group) wire the name onto the host's `ElementInternals` instead. Rendering is delegated to a new stateless directive, `renderFieldLabel` (`/directives/render-label`). Both are documented in Storybook (Mixins → Labelling mixin) with stories and tests.
- **`@adobe/spectrum-wc`**: `swc-text-field` now consumes `LabellingMixin` as its first proving-ground component: it renders a slotted `label` as a real `<label for>`, resolves `accessible-labelledby` to external elements, and wires the rendered `<input>` accordingly. Description/error-text association (`HelpTextMixin`) is tracked separately and not part of this change.
