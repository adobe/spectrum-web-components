## Usage

`FieldDescriptionMixin` adds description/error-text rendering and accessible description wiring to a host so components do not hand-roll it. It is one of two decoupled primitives for form-field labelling:

- **`FieldDescriptionMixin`** (`@adobe/spectrum-wc-core/mixins`): the `accessible-describedby` property, `description` / `error-text` slot presence tracking, and `renderFieldDescription()`.
- **`renderFieldDescription`** (`@adobe/spectrum-wc-core/directives/render-field-description`): the underlying render-only directive. The mixin owns and exposes it; use it directly only for stateless rendering without the mixin.

`LabellingMixin` (`@adobe/spectrum-wc-core/mixins`) is the companion mixin for accessible-name association; `swc-text-field` composes both.

### What it does

- **Combined description sources**: unlike accessible-name sources, a slotted `description` and an external `accessibleDescribedby` reference combine rather than override each other. The role element's `ariaDescribedByElements` lists the in-shadow description first, then the resolved external elements.
- **Invalid-gated error text**: error text is shown only while the host is invalid.
- **Conditional rendering**: renders nothing when there is no description or active error text.

### Basic usage

1. Apply the mixin to your base class: `class MyField extends FieldDescriptionMixin(SpectrumElement) {}`.
2. Override `roleElement` to return the element the description/error-message relationships should be wired onto.
3. Call `renderFieldDescription()` in your template.

For a host whose invalid state comes from another API, pass it explicitly, for example `renderFieldDescription({ invalid: this.fieldStatus === 'invalid' })` in text field. The component owns resolving that state; the mixin owns rendering and associating the appropriate description or error text.

```typescript
import { html, LitElement } from 'lit';
import { FieldDescriptionMixin } from '@adobe/spectrum-wc-core/mixins';

class MyField extends FieldDescriptionMixin(LitElement) {
  invalid = false;

  override get roleElement() {
    return this.renderRoot.querySelector('input');
  }

  render() {
    return html`
      <input />
      ${this.renderFieldDescription()}
    `;
  }
}
```

### Error text replaces the description while invalid

## Accessibility

### Features

- **Visible-message association**: `ariaDescribedByElements` references the visible message and external descriptions. Error text uses `aria-describedby`, not `aria-errormessage`.
- **No default live region**: help/error content is wired through `ariaDescribedByElements`, not an `aria-live` region, so a screen reader announces it when focus lands on the field.

### Best practices

- Pair `invalid` with slotted `error-text` so the invalid state is not conveyed by color alone.
- Use `accessibleDescribedby` for a description composed from light-DOM content the field doesn't own; it combines with, rather than replaces, a slotted `description`.

## API

### Constructor

`FieldDescriptionMixin(BaseClass)` returns `BaseClass` extended with the field-description API.

### Members

| Member                      | Description                                                                                                   |
| --------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `accessibleDescribedby`     | Space-separated element `id`s that describe the role element. Combines with a slotted `description`.          |
| `hasDescriptionSlotContent` | Read-only. Whether slotted `description` content is present.                                                  |
| `hasErrorTextSlotContent`   | Read-only. Whether slotted `error-text` content is present.                                                   |
| `roleElement`               | `@internal`. The element the resolved description/error relationships are wired onto.                         |
| `renderFieldDescription()`  | Renders the description/error-text markup for the current state (via the `renderFieldDescription` directive). |

### Related primitives

| Export                   | Module                                                        | Purpose                                                                                  |
| ------------------------ | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `renderFieldDescription` | `@adobe/spectrum-wc-core/directives/render-field-description` | Underlying field-description render; exposed via the mixin's `renderFieldDescription()`. |
| `LabellingMixin`         | `@adobe/spectrum-wc-core/mixins`                              | Companion mixin for accessible-name association.                                         |
