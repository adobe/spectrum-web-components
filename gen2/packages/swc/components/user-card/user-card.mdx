## Anatomy

A user card shares `preview`, `title`, `description`, the default slot, and `footer` with [Card](../?path=/docs/components-card--docs). It adds one slot:

- **`avatar`** (required): the person's avatar, shown between the preview and the content. Expects an [Avatar](../?path=/docs/components-avatar--docs) element.

The card manages the avatar's size (matching the card's own size) and outline attributes, overwriting any other set values. Use [Asset](../?path=/docs/components-asset--docs) for `preview` content instead of a plain `<img>`, same as [Card](../?path=/docs/components-card--docs).

## Options

### Sizes

Sizes match [Card](../?path=/docs/components-card--docs): five sizes (`xs`–`xl`, medium default) scale typography, padding, and maximum inline size. The one addition: size also sets the slotted avatar's own `size` attribute from a fixed scale (`xs`: `100`, `s`: `300`, `m`: `500`, `l`: `700`, `xl`: `900`), overwriting any `size` the consumer sets directly.

<Canvas of={Stories.Sizes} />

### Variants

Variants match [Card](../?path=/docs/components-card--docs)'s `primary`/`secondary`/`tertiary`; `quiet` is not supported.

<Canvas of={Stories.Variants} />

### Density

Density matches [Card](../?path=/docs/components-card--docs): `compact`, `regular` (default), and `spacious`.

<Canvas of={Stories.Density} />

### With preview

Populating the `preview` slot renders a wide banner image above the avatar, at a `3/1` aspect ratio by default. When a preview is present, the avatar is pulled up to overlap its bottom edge by half the avatar's own size; without a preview, the avatar sits flush at the top of its row. The card always sets `outline` on the avatar with a fixed 2px width, so it reads clearly against the preview.

## Behaviors

### Title as link

Identical to [Card](../?path=/docs/components-card--docs)'s `title-as-link`: wrap the `title` slot content in a real link and set the attribute to extend its hit area across the whole card surface.

<Canvas of={Stories.TitleAsLink} />

### Selectable

Identical to [Card](../?path=/docs/components-card--docs)'s `selectable`: makes the card focusable and dispatches `swc-card-click` on click, <kbd>Enter</kbd>, or <kbd>Space</kbd>.

<Canvas of={Stories.Selectable} />

## Accessibility

### Features

- The **`avatar`** slot expects an [Avatar](../?path=/docs/components-avatar--docs) element, which owns its own `alt`/`decorative` labeling contract; see its Accessibility section for that contract. The card does not add or manage the avatar's accessible name.
- **`title-as-link`** and **`selectable`** behave identically to [Card](../?path=/docs/components-card--docs); see its Accessibility section for details.

### Best practices

- When the avatar depicts the same person named in `title`, pass `alt=""` and set `decorative` on the avatar instead of giving it its own name, so a screen reader doesn't announce the name twice: `<swc-avatar slot="avatar" alt="" decorative>` alongside `<span slot="title">Jane Doe</span>`. This matches [Avatar](../?path=/docs/components-avatar--docs)'s own guidance for a name that already appears in adjacent context.
- For `title-as-link` and `selectable` usage guidance, see [Card](../?path=/docs/components-card--docs)'s Accessibility section.

## Upcoming features

Shared with [Card](../?path=/docs/components-card--docs):

- A horizontal card orientation is planned, alongside today's vertical layout.
- Multi-card selection will be handled by a future CardView container. The `selectable` attribute is the per-card groundwork for it: on its own it makes a card focusable and dispatches `swc-card-click`, but it does not render a "checked" selected state.
