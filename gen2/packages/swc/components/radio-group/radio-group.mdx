### Field status

The `field-status` attribute (`fieldStatus` property) accepts one status at a time: `disabled`, `invalid`, or `readonly`. The default is `undefined`. Assign `undefined` or remove the attribute to clear the status. A radio group has no `valid` status. `required` remains independent.

#### Disabled

`field-status="disabled"` disables every item and prevents selection and <kbd>Tab</kbd> access. The group does not block form validation and is excluded from `FormData`. To style a disabled group from outside, select `:state(disabled)`, which also matches when a `<fieldset disabled>` ancestor disables the group.

Use `field-status="readonly"` instead when users need to review the selection.

<Canvas of={RadioGroupStories.Disabled} />

#### Invalid

`field-status="invalid"` shows supplied `error-text` instead of the description. Without an `error-text` slot, the description stays visible in the error color. An alert icon shows beside the message or description, or on its own when there is neither, so the state never relies on color alone. Eligible groups fail validation and block submission, even when an item is selected.

Always pair `field-status="invalid"` with `error-text`. Explain what happened, why (if known), and how to fix it.

Native validation, such as `required`, does not set `field-status="invalid"` automatically. Set this status in your application as described in [showing and clearing errors](#showing-and-clearing-errors).

<Canvas of={RadioGroupStories.Invalid} />

#### Read-only

`field-status="readonly"` blocks selection changes while keeping focus movement between items. The group stays in `FormData` and does not block validation. Prefer read-only when users need access to a non-editable selection.

<Canvas of={RadioGroupStories.ReadOnly} />

### Required

`required` prevents a group with no selection from passing constraint validation. It does not set `field-status` or show an error. With a visible label, the default [necessity indicator](#necessity-indicator) adds a decorative asterisk.

### Form participation

`swc-radio-group` works with native forms, including validation, reset, and `FormData`. The group submits one entry under its `name`, holding the selected item's `value`, and nothing when no item is selected.

#### Showing and clearing errors

Set `fieldStatus = 'invalid'` and provide `error-text` to show an inline error. Neither happens automatically, and error text alone does not make the group invalid. Errors show when your application sets them, on a commit such as a selection change or on submit, not as users move through the items.

The plain text of `error-text` also becomes `validationMessage` and updates automatically when the content changes. Without it, the message is "Select an option." That message appears only in the browser's own validation bubble (a form without `novalidate`, or a call to `reportValidity()`) or where your code reads `validationMessage`. It is never shown inline. To change the message, change the text in `error-text`.

Clear the status explicitly when the error is resolved. Changing the selection does not clear it. Native constraints still affect `checkValidity()`, but do not set `fieldStatus` or show inline errors. Await `group.updateComplete` after changes before checking validity.

#### Validating a form

Use `novalidate` on the form and `checkValidity()` in your submit handler for inline errors instead of browser validation bubbles. With `novalidate`, the browser does not block submission, fire `invalid` events, or move focus, so your handler does all three:

1. Call `event.preventDefault()` before the first `await`. The browser does not wait for an async handler.
2. Clear a previous `invalid` status, and only `invalid`, so `disabled` and `readonly` stay.
3. Await `updateComplete`, then call `checkValidity()`.
4. If it returns `false`, set `fieldStatus = 'invalid'` and move focus to the group, or to another target such as an inline alert.
5. If it returns `true`, send the data.

<details>
<summary>Submit handler example</summary>

```html
<form novalidate>
  <swc-radio-group name="shipping" required>
    <span slot="label">Shipping method</span>
    <span slot="error-text">You must select a shipping method.</span>
    <swc-radio value="standard"><span slot="label">Standard</span></swc-radio>
    <swc-radio value="express"><span slot="label">Express</span></swc-radio>
  </swc-radio-group>
  <button type="submit">Submit</button>
</form>
```

```js
const form = document.querySelector('form');
const group = form.querySelector('swc-radio-group');

form.addEventListener('submit', async (event) => {
  event.preventDefault(); // before any await

  if (group.fieldStatus === 'invalid') {
    group.fieldStatus = undefined; // only invalid; keep disabled and read-only
  }
  await group.updateComplete;

  if (!group.checkValidity()) {
    group.fieldStatus = 'invalid'; // shows the error-text above
    group.focus();
    return;
  }

  // The group is valid. Send new FormData(form, event.submitter).
});
```

Do not call `form.submit()` to send the data. It skips validation and the `submit` event. Use a submit button, or `form.requestSubmit()`.

</details>

In this example, **Submit** clears the previous error and rechecks the selection. Accepted submissions are not sent anywhere. **Reset** restores the initial selection and clears the error.

<Canvas of={RadioGroupStories.FormParticipation} />

`group.focus()` moves focus to the group, so your handler can focus the group it found. Disabled and read-only groups do not block validation.

#### Reset

Reset restores the initial selection, which is the pre-checked item or the `selected` attribute, and clears `invalid` status. Disabled and read-only status are preserved, and a `required` group with no initial selection fails validation again.

<details>
<summary>Additional form behavior</summary>

- **Validation methods**: `checkValidity()` fires `invalid` on failure without changing `fieldStatus` or showing browser validation UI. `reportValidity()` also requests that UI, even with `novalidate`. Canceling `invalid` suppresses reporting without making validation pass. An invalid status sets `validity.customError`, and a required group with no selection sets `validity.valueMissing`.
- **Styling hooks**: style the invalid state from `field-status="invalid"`, and the disabled state from `:state(disabled)`. The group's `:invalid` match follows live validity, including before your application shows any error.

</details>
