## Anatomy

`swc-card-view-option-6` uses the same labelled single-column `grid`, `row`, and `rowheader` structure as Option 1, with one semantic row per card. Each card retains its native checkbox, Open button, and Share button. Only waterfall arrow navigation differs from Option 1.

## Options

### Grid

Uniform cards use Option 1's navigation: Left/Right follows collection order and Up/Down follows visual geometry.

<Canvas of={Stories.Grid} />

### Waterfall

Cards retain varied preview heights and use shortest-column placement. Only the vertical arrow axis navigates: Down moves to the next enabled card in semantic order and Up moves to the previous one, regardless of visual placement. Left/Right does not move focus.

<Canvas of={Stories.Waterfall} />

## Behaviors

In grid layout, <kbd>ArrowLeft</kbd> and <kbd>ArrowRight</kbd> move sequentially between enabled cards, mirrored in RTL. <kbd>ArrowUp</kbd> and <kbd>ArrowDown</kbd> move spatially above/below with horizontal overlap, as in Option 1.

In waterfall layout, <kbd>ArrowDown</kbd> and <kbd>ArrowUp</kbd> move forward/backward in semantic collection order. <kbd>ArrowLeft</kbd> and <kbd>ArrowRight</kbd> do not navigate. Movement stops at collection boundaries and skips disabled cards; it does not use visual distance or column membership.

<kbd>Home</kbd> and <kbd>End</kbd> reach the first/last enabled card in both
layouts. <kbd>Space</kbd> toggles selection and <kbd>Enter</kbd> opens the
focused card. Shift navigation selects a collection-order range in
multiple-selection mode. Tab visits the active card's checkbox and actions
before exiting; Shift+Tab reverses the path. Child actions keep native keys and
never also select the card.

## Accessibility

### Features

The grid reports one column and one row per card. Rows and rowheaders expose stable one-based row indices, and rowheaders expose column index 1. Selection uses `aria-selected` and labelled native checkboxes. The active card is the collection entry point; inactive cards' child controls have `tabindex="-1"`. The live status reports selected count.

The pros and cons below use Option 5's evaluation goals, with the waterfall navigation tradeoff added. Option 5's observed “x of y” speech is not a verified result for this new Option 1-based variant. Its one-column, multiple-row semantics must be tested separately; metadata alone does not guarantee positional announcements.

<Canvas of={Stories.Accessibility} />

### Pros

- Aligns navigation with semantic collection order.
- Targets “x of y” positional feedback for screen reader users, the benefit observed with Option 5; verify it for this variant.
- Arrow-key navigation provides an easy and intuitive route for sighted users navigating items.
- Provides a stable sequential route through every enabled card in both layouts.
- Retains selection, a single collection tab stop, and independently interactive children.
- Avoids semantic restructuring during responsive reflow.
- Waterfall navigation is easy to follow visually because it uses one predictable semantic traversal sequence.

### Cons

- Announced grid dimensions do not match visual columns once cards wrap or form a waterfall.
- As with Option 5, semantic dimensions and visual movement can create different screen reader expectations; this variant announces one column rather than Option 5's one row.
- Sequential waterfall movement can look surprising when adjacent collection items are not visual neighbors.
- Grid semantics still introduce screen reader mode changes and need user testing; indices do not guarantee useful position announcements.
- Waterfall navigation is slightly more tedious because reaching a distant card requires stepping through intervening items instead of taking a spatial shortcut.

### Best practices

Compare this variant directly with Options 1 and 5. Test complete forward/reverse waterfall traversal, ignored horizontal arrows, disabled cards, range selection, child controls, RTL, resize, and layout switches. Record actual positional speech and sighted keyboard task effort rather than assuming shared benefits establish accessibility conformance.
