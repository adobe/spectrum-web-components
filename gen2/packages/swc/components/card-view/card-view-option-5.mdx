## Anatomy

`swc-card-view-option-5` represents the entire collection as one semantic row, with one focusable `gridcell` per card. Each cell contains a photo, selection checkbox, primary action, and Share action. The grid reports one row and a column count equal to the number of cards; each cell reports its collection-order column index.

## Options

### Grid

Cards align in uniform visual rows. These visual rows do not create additional semantic rows. Left/Right traverses enabled cards in collection order, including across visual line breaks.

<Canvas of={Stories.Grid} />

### Waterfall

Cards are placed into the shortest visual column using measured heights. The semantic row and collection order remain unchanged. Left/Right still reaches every enabled card sequentially, even when the next card is not a visual neighbor.

<Canvas of={Stories.Waterfall} />

## Behaviors

Left/Right moves between enabled cells without cycling past the first or last card. In right-to-left layouts, Left moves forward and Right moves backward. Up/Down does not move focus because there is only one semantic row. Home/End reaches the first/last enabled card.

Space toggles selection and Enter opens the focused card. Shift plus Left/Right or Home/End selects a collection-order range, skipping disabled cards. Tab enters the active card's checkbox and actions, then exits the collection. Shift+Tab reverses that path. Only the active card's controls are in the tab order. Child actions do not also select the card, and their arrow keys are not intercepted by collection navigation.

## Accessibility

### Features

The collection exposes `grid > row > gridcell` semantics, `aria-rowcount="1"`, and `aria-colcount` equal to the collection size. The row has `aria-rowindex="1"`; each cell has its one-based `aria-colindex`, accessible name, and selection state when selection is enabled. Disabled cards remain represented but are skipped by keyboard navigation. Checkboxes expose their checked states, and a live status reports the selected count.

Resizing, zooming, and switching layouts update visual geometry without regrouping cells or changing their semantic indices. Column counts and indices describe the logical collection, not visual columns. Actual positional announcements depend on the browser, screen reader, navigation mode, and verbosity; these attributes do not guarantee spoken “x of y.”

### Pros

- Aligns horizontal navigation with the announced single-row structure.
- Provides a stable sequential route through every enabled card in both layouts.
- Retains selection, a single collection tab stop, and independently interactive children.
- Avoids semantic restructuring during responsive reflow.

### Cons

- Announced columns do not match visual columns once cards wrap or form a waterfall.
- Up/Down does not provide spatial navigation, which sighted keyboard users may expect.
- Sequential waterfall movement can look surprising when adjacent collection items are not visual neighbors.
- Grid semantics still introduce screen reader mode changes and need user testing; column indices do not guarantee useful position announcements.

### Best practices

Treat this as a comparison prototype, not an accessibility sign-off. Compare it with the single-column models and native list using real screen reader users. Test finding the seventh card, identifying position and total count, selecting two cards, and operating child actions. Cover NVDA with Chrome/Firefox, JAWS with Chrome, VoiceOver with Safari using both ordinary arrows and VoiceOver commands, Narrator with Edge, VoiceOver on iOS, and TalkBack.

Also test disabled cards, selection modes, Tab/Shift+Tab entry and exit, right-to-left direction, narrow viewports, zoom, and layout switches while focus remains in the collection. Do not infer spoken output from DOM attributes or simulated announcements.

## Upcoming features

Virtualization and dynamic loading are deferred. All cards are loaded in this prototype; future virtualization must preserve logical column indices and communicate the total count where known.
