## Anatomy

- A labelled grid contains one semantic row for the entire collection.
- Each card is a focusable `gridcell` with its collection-order column index.
- Each cell contains a photo, selection checkbox, Open action, and Share action.

## Options

### Grid

Cards align in uniform visual rows without adding semantic rows. Arrow keys follow geometry, wrapping to the opposite end of the same aligned visual row or column at its boundary.

<Canvas of={Stories.Grid} />

### Waterfall

Cards fill visual columns from top to bottom in collection order, then continue across the layout. Varied card heights make a visual row an overlapping band rather than a fixed semantic row. Wrapping remains local to that band.

<Canvas of={Stories.Waterfall} />

## Behaviors

<kbd>ArrowLeft</kbd> and <kbd>ArrowRight</kbd> move spatially within an aligned
visual row; <kbd>ArrowUp</kbd> and <kbd>ArrowDown</kbd> move spatially within an
aligned visual column. At a boundary, navigation chooses the opposite extreme
among aligned enabled cards. These visual directions also apply in RTL. Wrapping
does not advance through the whole collection. <kbd>Home</kbd> and
<kbd>End</kbd> reach the first and last enabled cards.

<kbd>Space</kbd> toggles selection and <kbd>Enter</kbd> opens the focused card.
Holding <kbd>Shift</kbd> with an arrow key, <kbd>Home</kbd>, or <kbd>End</kbd>
selects a collection-order range, skipping disabled cards. <kbd>Tab</kbd> visits
the active card's checkbox and actions, then leaves the collection;
<kbd>Shift</kbd> + <kbd>Tab</kbd> reverses that path. Child controls retain
their own keyboard behavior.

## Accessibility

### Features

The collection exposes `grid > row > gridcell`, `aria-rowcount="1"`, and a column count equal to the collection size. Each cell has a one-based collection-order column index, accessible name, and selection state when selection is enabled. Disabled cards remain represented but are skipped by navigation. Native checkboxes expose checked state, and a live status reports the selected count.

### Best practices

Local wrapping can repeatedly visit one visual band without reaching the rest of the collection. Compare option 2B's boundary stops with this option's local wrapping and option 2D's full collection cycling. Do not equate wrapping with complete single-axis traversal.

One semantic row does not explain vertical navigation. Verify actual position announcements, wrapping boundaries, child actions, range selection, disabled cards, keyboard entry and exit, RTL, zoom, and layout changes with screen reader and keyboard users. Semantic indices alone do not establish usability or conformance.
