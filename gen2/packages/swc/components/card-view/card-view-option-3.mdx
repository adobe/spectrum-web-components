## Anatomy

`swc-card-view-option-3` uses a native `ul` and `li` for the collection. Each card preserves its own checkbox, primary button, and Share button. Each `li` sets `aria-setsize` to the total card count and `aria-posinset` to its one-based position, including disabled cards. Selection is conveyed by the checkbox rather than `aria-selected` on a list item.

## Options

### Grid

Uniform visual rows do not change the native list's DOM reading order or normal page tab order.

<Canvas of={Stories.Grid} />

### Waterfall

Shortest-column placement changes visual positions. Reading and Tab order remain sequential; vertical list-item arrows follow measured geometry.

## Behaviors

<kbd>ArrowLeft</kbd> and <kbd>ArrowRight</kbd> move sequentially between enabled
list items, mirrored in RTL. <kbd>ArrowUp</kbd> and <kbd>ArrowDown</kbd> move
spatially above/below with horizontal overlap. Movement stops at boundaries;
<kbd>Home</kbd> and <kbd>End</kbd> reach the first/last enabled item. Only the
active list item has `tabindex="0"`.

<kbd>Tab</kbd> and <kbd>Shift</kbd> + <kbd>Tab</kbd> still visit every enabled
checkbox and action in normal order. Child-control arrow keys are not
intercepted. <kbd>Space</kbd> operates the focused native control. There is no
custom range selection; Open and Share never toggle selection.

## Accessibility

### Features

Native list semantics preserve content and independent controls. Selection uses labelled checkboxes. Disabled controls are excluded from the tab sequence by native behavior. Resize does not change DOM order.

<Canvas of={Stories.Accessibility} />

### Pros

- Avoids conflicting row/column announcements while providing supplemental list-item arrows.
- Supports familiar reading and control interaction without relying on screen reader focus mode.
- Keeps real child actions and explicit selection controls.

### Cons

- Large collections have many tab stops and may be slower for frequent keyboard users.
- Supplemental arrows and list-item tab stops require discovery; there is no composite keyboard range selection.
- Native list counts and position metadata do not guarantee that a focused child control announces "x of y."

### Best practices

Compare task effort against the grid options and consider suitable bypass controls for large collections. Do not remove normal tab access merely to add optional arrow shortcuts. Test positional speech, selection, reading order in waterfall, and mobile exploration before selecting this approach.
