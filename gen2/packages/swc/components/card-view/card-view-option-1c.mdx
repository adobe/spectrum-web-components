## Anatomy

- A labelled grid represents the collection as one semantic column.
- Each card is a row containing a focusable `gridcell`.
- Each cell contains a photo, selection checkbox, Open action, and Share action.

## Options

### Grid

Cards align in uniform visual rows. All four arrow keys follow geometry, wrapping to the opposite end of the same aligned visual row or column at its boundary.

<Canvas of={Stories.Grid} />

### Waterfall

Cards have varied heights. Alignment uses overlap on the perpendicular axis, so a visual row is a band of overlapping cards rather than a fixed semantic row. Wrapping remains local to that aligned band.

<Canvas of={Stories.Waterfall} />

## Behaviors

<kbd>ArrowLeft</kbd> and <kbd>ArrowRight</kbd> move spatially within an aligned
visual row; <kbd>ArrowUp</kbd> and <kbd>ArrowDown</kbd> move spatially within an
aligned visual column. When no enabled neighbor exists in that direction,
navigation chooses the opposite extreme among aligned enabled cards. These
visual directions also apply in RTL. This is local wrapping, not a cycle through
the whole collection. <kbd>Home</kbd> and <kbd>End</kbd> reach the first and
last enabled cards.

<kbd>Space</kbd> toggles selection and <kbd>Enter</kbd> opens the focused card.
Holding <kbd>Shift</kbd> with an arrow key, <kbd>Home</kbd>, or <kbd>End</kbd>
selects a collection-order range, skipping disabled cards. <kbd>Tab</kbd> visits
the active card's checkbox and actions, then leaves the collection;
<kbd>Shift</kbd> + <kbd>Tab</kbd> reverses that path. Child controls retain
their own keyboard behavior.

## Accessibility

### Features

The collection preserves `grid > row > gridcell` semantics with one semantic column and a row per card. Cards expose accessible names and selection state when selection is enabled. Disabled cards remain represented but are skipped by navigation. Native checkboxes expose checked state, and a live status reports the selected count.

### Best practices

Local wrapping can revisit the same visual band without reaching other cards. Do not describe it as a guarantee that every card is reachable by repeating one arrow. Compare it with option 1B, which stops at spatial boundaries, and option 1E, which cycles through collection order.

The announced single column and visual navigation still differ. Verify actual position announcements, wrapping boundaries, disabled cards, child actions, selection, keyboard entry and exit, RTL, zoom, and layout changes with keyboard and screen reader users. This prototype does not establish usability or conformance.
