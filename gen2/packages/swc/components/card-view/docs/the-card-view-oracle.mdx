<p className="eyebrow">The card-detail experiment</p>
<h2 id="oracle-disclosure-title">Reveal details on entry.</h2>
<p>We are implementing Google Drive's reported <code>aria-hidden</code> strategy for cards in all nine named grid and masonry navigation examples. Each <code>swc-card</code> starts with <code>aria-hidden="true"</code> and <code>aria-live="polite"</code>. Its containing gridcell stays exposed and focusable, with an accessible name. The updated interaction specifies the visually hidden description "press tab for more info" on every operating system. The six semantic references, including the single-column grid, remain unchanged. This is a Google-inspired experiment, not a claim of identical behavior.</p>
<p>With focus on a gridcell, <kbd>Tab</kbd> must expose its card with <code>aria-hidden="false"</code> before moving focus to the first enabled focusable element inside it, without selecting the card or activating an action. Subsequent <kbd>Tab</kbd> presses follow the card's control order and then leave the collection; <kbd>Shift</kbd> + <kbd>Tab</kbd> reverses the path. Hidden controls remain outside the sequential tab order until revealed. This replaces the modifier-key toggle with ordinary <kbd>Tab</kbd> entry, not a More info button. The cell's accessible name preserves the title while its card is hidden. Tab-to-reveal is the implementation target; runtime validation remains pending.</p>
<p>Focus safety is not yet complete: the regression for pointer or programmatic focus entering a hidden card control currently fails.
