## Anatomy

A toast container consists of:

- **Region**: a fixed-position wrapper with `role="region"` and a label that counts the queued notifications
- **Toast**: the front `<swc-toast>` that the container renders, with an optional variant icon, a message, an optional action button, and a close button

The container does not take children. Add toasts to the shared `ToastQueue` and the container renders them.

## Options

### Variants

Set `variant` when you add a toast. A toast has four semantic variants: `neutral` (default), `info`, `positive`, and `negative`. The `info`, `positive`, and `negative` variants show a matching icon.

### Placement

Set `placement` on the container to choose where toasts appear: `bottom` (default), `bottom-end`, `top`, or `top-end`. The `-end` placements sit at the end side of the viewport, which is the right in left-to-right layouts and the left in right-to-left layouts.

## Behaviors

### Adding and removing toasts

Add one `<swc-toast-container>` to your page, then use `ToastQueue` to manage toasts. `ToastQueue.add()` returns a key that identifies the entry.

```javascript
import '@adobe/spectrum-wc/components/toast-container/swc-toast-container.js';
import { ToastQueue } from '@adobe/spectrum-wc/components/toast-container/index.js';

const key = ToastQueue.add('File saved', { variant: 'positive' });

ToastQueue.close(key);
ToastQueue.clear();
```

`add()` accepts these options:

- `variant`: `neutral` (default), `info`, `positive`, or `negative`
- `iconLabel`: overrides the variant icon's default label (an empty string makes the icon decorative)
- `closeLabel`: the accessible name of the close button, default "Close"
- `timeout`: the auto-dismiss duration in milliseconds
- `actionLabel`: the label for the action button
- `onAction`: called when the action button is activated
- `shouldCloseOnAction`: closes the toast after the action runs, default `false`
- `onClose`: called once when the toast is removed

These options apply to a toast when you add it. Changing them later does not affect toasts that are already in the queue. This differs from `placement` on the container, which updates right away.

The queue keeps every toast you add, but the container renders only the newest one. When it closes, the next toast in the queue appears. The region label counts every queued toast, including the ones that are waiting.

`ToastQueue.close(key)` closes one toast and calls its `onClose`. `ToastQueue.clear()` removes all toasts and does not call any `onClose` callbacks. A toast that a listener keeps open by canceling its `swc-close` event stays in the queue and does not call `onClose`.

Connect only one `<swc-toast-container>` per page. A second container logs a warning during development.

### Auto-dismiss

A toast stays until it is closed unless you set `timeout`. Positive values are raised to a minimum of 6000 milliseconds. `null`, `0`, and negative values turn auto-dismiss off.

Only the toast that is showing counts down. When the next toast appears, its timer starts from the full duration. The timer pauses while a pointer or keyboard focus is anywhere in the region, and it resumes when both have left.

### Actions

Set `actionLabel` and `onAction` to add an action button to a toast. Activating the button calls `onAction` and leaves the toast open unless you set `shouldCloseOnAction`. A toast with an action never auto-dismisses, so users have time to reach the button. If you also set `timeout`, a warning appears during development and the timeout is ignored.

### Text wrapping

Long messages wrap within the toast's maximum width. When the toast has an action, the action moves below the text. Long unbroken words break instead of overflowing the toast.

<Canvas of={ToastContainerStories.ToastTextWrapping} />

### Focus

Opening a toast does not move focus. When the last toast closes while focus is inside the region, focus returns to the element that had it before the user entered the region. If focus has already moved elsewhere, it stays where it is.

## Accessibility

### Features

The region has `role="region"` and an accessible name that reads "1 notification." or "N notifications." based on the number of queued toasts. To localize it, set the `getRegionLabel` property on `<swc-toast-container>` to a function that takes the count and returns the label, for example `container.getRegionLabel = (count) => ...`. A function lets you handle plural forms for your language. It is a property only, not an attribute. The region has `tabindex="-1"`, so it can receive focus from script but is not part of the normal Tab sequence.

While a toast is showing, <kbd>F6</kbd> and <kbd>Shift</kbd> + <kbd>F6</kbd> move focus into the region from anywhere on the page. Pressing either key again returns focus to where it was. Both keys keep their normal browser behavior when no toast is showing.

Each `<swc-toast>` has `role="alertdialog"`, `aria-modal="false"`, and `tabindex="0"`, with an inner `role="alert"` wrapper so screen readers announce the message. The container reveals the message shortly after the toast opens, so assistive technology registers the live region first. The toast's accessible name comes from its message. For `info`, `positive`, and `negative` toasts, the name starts with the icon's label (for example, "Error File could not be saved"), so a screen reader reads it when focus moves onto the toast. Test tooling that ignores `ElementInternals`, such as Playwright ARIA snapshots, shows these toasts without a name. In Safari, VoiceOver reads only the message when focus moves onto the toast, because WebKit does not include the icon in the name. The variant is still announced when the toast appears.

### Best practices

- The `info`, `positive`, and `negative` variant icons are announced by default as "Information", "Success", and "Error". The `neutral` variant has no icon. Because these defaults are English, set `iconLabel` to a translated label when your page is in another language.
- If the message already states the status, set `iconLabel` to an empty string so the icon is decorative and screen readers do not say it twice.
- Provide a descriptive `actionLabel` for the action button.
