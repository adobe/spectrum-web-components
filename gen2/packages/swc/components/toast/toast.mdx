## Anatomy

A toast consists of:

- **Variant icon**: communicates the semantic variant when `variant` is `info`, `positive`, or `negative`
- **Message**: provided through the default slot
- **Action**, configured with `actionLabel`: Toast renders one `<swc-button>` with the fixed secondary, outline, static-white treatment and dispatches `swc-toast-action` when activated
- **Close button**: dismisses the toast

## Behaviors

### Methods

When the toast is open, call `close()` to request dismissal. It dispatches the cancelable `swc-close` event synchronously. If a listener cancels the event, `open` remains `true`.

Assigning `open = false` directly dispatches `swc-close` during the update cycle. If canceled, the property is restored to `true` during that update.

```javascript
const toast = document.querySelector('swc-toast');

toast?.addEventListener('swc-close', (event) => {
  event.preventDefault();
});

toast?.close();
```

## Accessibility

### Features

The `<swc-toast>` host has `role="alertdialog"`, `aria-modal="false"`, and `tabindex="0"`. An inner wrapper has `role="alert"` and `aria-atomic="true"` so the message can be announced without moving focus when the toast opens.

The host's accessible name depends on the default-slot content:

- Bare message text produces an `aria-label` derived from that text.
- A single light-DOM message element with an `id` is referenced by `aria-labelledby`.

The first example uses bare text. The second uses an ID-bearing `<span>`. Inspect each `<swc-toast>` host to compare the resulting attributes.

### Best practices

- Use bare text when the message does not need its own element.
- Use one ID-bearing message element when the message already has stable light-DOM markup that the host can reference.
- Write a message that communicates the variant on its own, because the variant icon is decorative by default and screen readers do not announce it.
- Set `icon-label` only when the icon needs its own announcement; a label can repeat meaning the message already carries.
- Set `actionLabel` to render the optional action button.
- Provide a descriptive `actionLabel` for the optional action button.
- Listen for the bubbling, composed `swc-toast-action` event to handle action activation. Toast does not close itself; the queue owns the callback and optional close-on-action behavior.
