## Anatomy

A toast consists of:

- **Variant icon**: communicates the semantic variant when `variant` is `info`, `positive`, or `negative`
- **Message**: provided through the default slot
- **Action**, configured with `actionLabel`: Toast renders one `<swc-button>` with the fixed secondary, outline, static-white treatment and dispatches `swc-toast-action` when activated
- **Close button**: dismisses the toast

## Options

### Variants

A toast has four semantic variants: `neutral` (default), `info`, `positive`, and
`negative`. The `info`, `positive`, and `negative` variants show a matching icon.

<Canvas of={ToastStories.Variants} />

### Action

Set `action-label` to show an optional action button. Toast renders the button
with or without a variant icon and dispatches `swc-toast-action` when it is
activated.

<Canvas of={ToastStories.Action} />

## Behaviors

### Text wrapping

Long messages wrap within the toast's maximum width. When the toast has an
action, the action moves below the text. Long unbroken words break instead of
overflowing the toast.

<Canvas of={ToastStories.TextWrapping} />

### Methods

When the toast is open, call `close()` to request dismissal. It dispatches the cancelable `swc-close` event synchronously. If a listener cancels the event, `open` remains `true`.

Assigning `open = false` directly dispatches `swc-close` during the update cycle. If canceled, the property is restored to `true` during that update.

```javascript
const toast = document.querySelector('swc-toast');

toast?.addEventListener('swc-close', (event) => {
  event.preventDefault();
});

toast?.close();
```

## Accessibility

### Features

The `<swc-toast>` host has `role="alertdialog"`, `aria-modal="false"`, and `tabindex="0"`. An inner wrapper has `role="alert"` and `aria-atomic="true"` so the message can be announced without moving focus when the toast opens. Toast adds the message to the live region two frames after `open` changes from `false` to `true`, so screen readers announce it reliably. A toast that renders already open does not use this delay.

The host's accessible name comes from the message in the default slot.

### Best practices

- Write a message that communicates the variant on its own, because the variant icon is decorative by default and screen readers do not announce it.
- Set `icon-label` only when the icon needs its own announcement. If the message already states the status, a label makes screen readers say it twice.
- Set `actionLabel` to render the optional action button.
- Provide a descriptive `actionLabel` for the optional action button.
- Listen for the bubbling, composed `swc-toast-action` event to handle action activation. Toast does not close itself; the queue owns the callback and optional close-on-action behavior.
