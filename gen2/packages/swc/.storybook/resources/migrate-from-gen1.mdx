# Migrate from Gen1

Move your app from SWC Gen1 (`@spectrum-web-components/*`) to Gen2 (`@adobe/spectrum-wc`) one component at a time, with both running side by side.

- **For:** application developers
- **Time:** about 2 hours of setup across 8 phases, then about 30 minutes per component
- **Before you start:** confirm that migrating fits your timeline with [Gen1 vs Gen2](/docs/learn-about-swc-gen1-vs-gen2--docs)

## Plan your migration

Gen1 and Gen2 run side by side, so you don't migrate everything at once. To learn why, see [How Gen1 and Gen2 coexist](/docs/learn-about-swc-gen1-vs-gen2--docs#how-gen1-and-gen2-coexist).

- [ ] List the `@spectrum-web-components/*` packages in your `package.json`, and find each `<sp-theme>` element.
- [ ] For each `<sp-*>` component, find its **Migration guide** page in the **Components** section of the sidebar. A component without one is still Gen1 only, so keep its package installed.
- [ ] Check each component's docs page for an **Upcoming features** section, which lists Spectrum 2 features that haven't shipped yet.
- [ ] If you're waiting on a Gen1 bug fix, check the [Gen1 bug policy](/docs/resources-support-and-compatibility--docs#gen1-bug-policy).
- [ ] Pick a first route or feature area, so few pages load both generations at once.

To have an AI coding agent run these phases, install the migration skill from [Build with AI](/docs/resources-build-with-ai--docs).

You should see a list of components to migrate now and components to keep on Gen1.

## Phase 1: Install Gen2

1. Add `@adobe/spectrum-wc` and keep your existing `@spectrum-web-components/*` packages:

   ```bash
   yarn add @adobe/spectrum-wc
   ```

Gen2 ships as one package, and you import each component from its own subpath. With npm or pnpm, use `npm install` or `pnpm add`.

You should see `@adobe/spectrum-wc` in your `package.json` dependencies, next to your Gen1 packages.

## Phase 2: Align Gen1 visually with Spectrum 2

1. Import the Gen1 Spectrum 2 theme next to `sp-theme`:

   ```ts
   import '@spectrum-web-components/theme/sp-theme.js';
   import '@spectrum-web-components/theme/src/spectrum-two/themes.js';
   ```

2. Set `system="spectrum-two"` on your existing `<sp-theme>`:

   ```html
   <sp-theme system="spectrum-two" color="light" scale="medium">
     <!-- existing sp-* components -->
   </sp-theme>
   ```

You should see your Gen1 components use the same colors, border radii, and icons as Gen2.

## Phase 3: Add the Gen2 stylesheet and theme classes

Gen2 doesn't use `<sp-theme>`. CSS classes and standard HTML attributes on a root element set the theme, scale, language, and direction.

1. Import the stylesheet once, at your app entry:

   ```ts
   import '@adobe/spectrum-wc/swc.css';
   ```

2. Add `swc-theme` and one color class to your root element:

   ```html
   <html class="swc-theme swc-theme--light"></html>
   ```

3. Move each remaining `<sp-theme>` setting to the root element:

   | Gen1 (`<sp-theme>`)        | Gen2 (root element)                                       |
   | -------------------------- | --------------------------------------------------------- |
   | `color="light"` / `"dark"` | `class="swc-theme swc-theme--light"` / `swc-theme--dark`  |
   | `scale="medium"` / `large` | `class="swc-theme swc-theme--sizeM"` / `swc-theme--sizeL` |
   | `lang="ja"` (on element)   | `lang="ja"` on `<html>` or the scoping element            |
   | `dir="rtl"`                | `dir="rtl"` on `<html>` or the scoping element            |

Keep `<sp-theme>` around your remaining `<sp-*>` components until phase 8. For other color classes or a theme scoped to one region, see [Theme and scales](/docs/guides-customization-theme-and-scales--docs).

You should see `color-scheme: light` on `<html>` in your browser's **Computed** styles.

## Phase 4: Load Adobe Clean Spectrum VF

Gen2 uses Adobe Clean Spectrum VF, the Spectrum 2 font family. It looks the same as Adobe Clean, the Gen1 font, but has updated metrics for vertical alignment inside components.

1. Load the font with the Adobe Fonts, CDN, or self-hosted setup in the [Fonts guide](/docs/guides-customization-fonts--docs).

You should see Adobe Clean Spectrum VF listed as the rendered font when you inspect `<swc-*>` text in your browser's dev tools.

## Phase 5: Replace components one at a time

Repeat this phase for each `<sp-*>` component that has a Gen2 version.

1. Open the component's migration guide, such as the [Badge migration guide](/docs/components-badge-migration-guide--docs). It lists changes to attributes, slots, events, and default values.
2. Update the import to the per-element path:

   ```ts
   // Before
   import '@spectrum-web-components/badge/sp-badge.js';

   // After
   import '@adobe/spectrum-wc/components/badge/swc-badge.js';
   ```

3. Rename the tag, such as `<sp-badge>` to `<swc-badge>`, and apply the attribute changes from the migration guide.
4. Remove the component's Gen1 import once its last `<sp-*>` usage is gone.

> ⚠️ **Important:** Some defaults change between generations. For example, Badge's default `variant` changes from `informative` to `neutral`, and [Tabs](/docs/components-tabs-migration-guide--docs) now selects a tab on arrow-key focus by default.

You should see the `<swc-*>` element render in place of the `<sp-*>` element, with no dev-mode warnings in the console.

## Phase 6: Migrate styling

Gen2 replaces the `--mod-*` custom property API with a smaller `--swc-*` API. It isn't a 1:1 replacement, because Spectrum 2 updates component styles.

1. Review the migrated component in your app before you rewrite its `--mod-*` overrides.
2. Delete the overrides you no longer need.
3. Rename the rest with the mapping table in the component's migration guide:

   ```css
   /* Before */
   sp-badge {
     --mod-badge-height: 24px;
     --mod-badge-corner-radius: 4px;
     --mod-badge-label-icon-color: var(--spectrum-gray-900);
   }

   /* After */
   swc-badge {
     --swc-badge-height: 24px;
     --swc-badge-corner-radius: 4px;
     --swc-badge-label-icon-color: var(--swc-gray-900);
   }
   ```

The general rule: `--mod-` becomes `--swc-`, and `--spectrum-` token references also become `--swc-`, because Gen2 republishes Spectrum 2 tokens under its own namespace. For more on overrides, see [Component styles](/docs/guides-customization-component-styles--docs).

You should see the migrated component match your design, with no `--mod-*` or `--spectrum-*` references left in its CSS.

## Phase 7: Validate your app

1. Run your type check, such as `tsc --noEmit`.
2. Run the tests that cover the migrated components.
3. Build the app, and review each migrated page in the browser.

You should see the type check, tests, and build pass, and each migrated page behave as before, apart from changes listed in the migration guides.

## Phase 8: Decommission Gen1

Do this phase once no `<sp-*>` element remains in your app.

1. Remove the `@spectrum-web-components/*` packages from your `package.json`.
2. Remove the `<sp-theme>` element and its `@spectrum-web-components/theme/*` imports.
3. Remove any remaining `--mod-*` overrides from your CSS.

You should see no matches for `@spectrum-web-components` or `<sp-` when you search your source code.

## Troubleshooting

| Symptom                                                  | Cause                                               | Fix                                                                                            |
| -------------------------------------------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Gen1 components look different from their Gen2 neighbors | `<sp-theme>` doesn't use the `spectrum-two` system. | Complete [phase 2](#phase-2-align-gen1-visually-with-spectrum-2).                              |
| `<swc-*>` components render without Spectrum 2 styles    | `@adobe/spectrum-wc/swc.css` isn't imported.        | Complete [phase 3](#phase-3-add-the-gen2-stylesheet-and-theme-classes).                        |
| Text renders in a system font                            | Adobe Clean Spectrum VF isn't loaded.               | Follow the [Fonts guide](/docs/guides-customization-fonts--docs).                              |
| A migration guide doesn't cover your case                | The gap isn't documented yet.                       | [Open an issue on GitHub](https://github.com/adobe/spectrum-web-components/issues/new/choose). |
