## Anatomy

- **Status icon**: Decorative workflow icon selected by the variant; neutral messages have no icon.
- **Message**: One text span in the default slot, which can include links.
- **Optional action**: One named button in the `actions` slot.
- **Required dismissal**: Exactly one [Close button](../?path=/docs/components-close-button--docs) in the `dismiss` slot, with a localized `accessible-label`.

The composed order is icon, message, optional action, then dismissal. Keep consumer markup in that same order. There is no separate heading slot.

## Options

### Semantic variants

Set the `variant` HTML attribute to `informative`, `positive`, `notice`, `negative`, or `neutral`. Omit it for the informative appearance. This is a CSS-only attribute: use markup or `setAttribute('variant', value)`, not a `variant` JavaScript property.

Choose an appearance with the `variant` select in Storybook controls.

Informative messages use an info-circle icon; positive messages use checkmark-circle; notice messages use alert-diamond; negative messages use alert-triangle. Include the status meaning in the message when it matters. Color and decorative icons do not replace meaningful text.

The close button is always inline. There is no placement attribute or floating layout.

### Optional action

Always provide one `swc-close-button` through `dismiss`. The `actions` slot accepts zero or one action button, in addition to the close button. Applications handle their `click` events; the pattern does not generate controls, dismiss itself, or validate slot cardinality at runtime.

<Canvas of={Stories.OptionalControls} />

Links belong in the message content's default slot, not in `actions`. Place them inline with the text, or use `<br>` to start a separate line within the same message span.

The `--swc-thread-alert-*` properties in the generated API table provide token-backed overrides for the surface, border, typography, spacing, and status icon. Child controls retain their own styling APIs.

## Behaviors

### Text wrapping

The pattern fills its container and grows with its content. Message text wraps, including long request identifiers, instead of truncating. Controls stay in normal flow and can wrap when space is constrained. The 451px width in these examples belongs to the demo, not the component.

The minimum height uses `component-height-100`: 32px at the default scale and 40px at the large scale. This is a minimum, not a fixed height; controls and wrapped text can make the message taller. Override it with `--swc-thread-alert-min-block-size`.

## Accessibility

### Features

Static messages have no generated role, live region, heading, or automatic focus. Decorative icons stay out of the accessibility tree.

The message host is non-interactive and is not a focus target. Only the child buttons and links within the message content participate in keyboard navigation.

Slotted controls keep their existing native semantics, accessible names, keyboard activation, and focus indicators. <kbd>Tab</kbd> and <kbd>Shift</kbd> + <kbd>Tab</kbd> move between controls in composed order; <kbd>Enter</kbd> and <kbd>Space</kbd> activate buttons. Links retain native link behavior. There is no toolbar, focus trap, arrow-key navigation, or Escape-to-dismiss handler.

### Best practices

Give each action visible text, or use the existing `accessible-label` API for icon-only buttons. A close button always needs a localized `accessible-label`, such as `Dismiss message`. Do not add a redundant button role or name the layout wrapper after a design layer.

Before removing a message containing focus, move focus to an appropriate remaining control.

Use meaningful message text that conveys the status without relying on color or the decorative icon. Manage the surrounding page's heading structure in the application.

Keep controls at least 24 by 24 CSS pixels. Preserve visible, unclipped focus indicators. The surface and border are translucent: they use 2% and 3% black in light mode, and white at the same opacities in dark mode. Verify text, icons, and focus indicators against the resulting composite color on the application's actual background in every supported theme.

The default control focus indicator falls below 3:1 contrast when the pattern sits on a dark `gray-100` background. Use a suitable application surface, or adjust the child controls' focus-indicator styling and verify contrast again. Transparency does not guarantee contrast on arbitrary backgrounds.

Automated checks do not establish WCAG conformance. Screen-reader announcement timing, reading order in the consuming page, and appropriate focus restoration after dismissal also need manual review.

### Dynamic insertion

The app announces dynamically inserted content through a live region that exists before the change, without moving focus to the message. Do not add `role="alert"`, `role="status"`, or `aria-live` to the thread alert itself, or make its host focusable.

This application example exposes the pre-existing live region as visible announcement text so its updates can be inspected. It is not part of the component's shadow DOM.
