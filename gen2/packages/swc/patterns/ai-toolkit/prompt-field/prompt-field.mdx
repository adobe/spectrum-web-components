## Anatomy

A prompt field consists of:

1. **Box**: white card container with shadow, starting as a taller multiline card by default.
2. **Input area**: visually hidden label + textarea.
3. **Action bar**: upload trigger (left) and send/stop action (right), shown on its own row.
4. **Footer**: legal disclaimer rendered below the prompt surface. Required in product implementations.

## Options

### Sizes

`size` sets the prompt field's overall scale, adjusting icon spacing, padding, and text size:

- **Small (`s`)**: compact spacing and typography; use it when the prompt field's primary context is a side panel, docked composer, or other space-constrained layout
- **Medium (`m`)** (default): standard spacing and typography for full-width or primary composer placements

<Canvas of={PromptFieldStories.Sizes} />

### Variant

`variant` sets the intensity of the AI brand treatment (the gradient ring, background wash, and glow):

- **`subtle`**: understated treatment; the gradient ring is revealed on hover
- **`balanced`** (default): visible gradient ring and background wash
- **`prominent`**: strongest treatment, adding an outer glow

Every layer derives from a single hue, so overriding `--swc-prompt-field-brand-color` rethemes all three variants at once.

<Canvas of={PromptFieldStories.Variant} />

### Status indicator

A pixel loader sits at the start of the input row. It rests on a settled frame while idle and animates while **`generating`**. A single **`loader`** attribute sets its artwork, passed straight through to `swc-pixel-loader`:

- An **icon name** (default `aiLogo`): the single icon the loader builds and holds.
- A **preset name** (`cc`, `dc`, `exp`, `analyze`, `mega`): a themed icon sequence cycled one per loop.

The two name sets don't overlap, so one attribute covers both.

The indicator is decorative (`aria-hidden`); the generating state is conveyed to assistive technology by the stop button that replaces send.

The textarea grows with content up to `--swc-prompt-field-max-block-size` (default `40vh`). Override the custom property to raise or lower this ceiling, e.g. `40%` of a sized parent:

```html
<div style="display: flex; block-size: 400px;">
  <swc-prompt-field
    style="--swc-prompt-field-max-block-size: 40%;"
  ></swc-prompt-field>
</div>
```

`min-rows`/`max-rows` add an optional row-count cap on top of this. Unset, only `--swc-prompt-field-max-block-size` applies.

### Legal disclaimer

Every prompt field in production must include Legal-approved disclaimer copy below the composer. Slot your product's approved text into **`legal`**: wording, links, and locale are consumer-owned, not baked into the component.

Slotted `legal` content inherits the footer typography automatically. When it contains links, add the `swc-Typography--links` class to the wrapping element so the links inherit that typography and render in the subdued neutral color instead of the default accent blue. `swc-prompt-field` logs a development warning when the `legal` slot is empty.

```html
<swc-prompt-field>
  <p slot="legal" class="swc-Typography--links">
    Responses are generated using AI, and may be inaccurate. Check before using.
    <a
      href="https://www.adobe.com/legal/licenses-terms/adobe-gen-ai-user-guidelines.html"
    >
      AI User Guidelines
    </a>
  </p>
</swc-prompt-field>
```

### Attachment

Attachment layout is inferred from the **`attachment`** slot content:

- No slot content: no attachment region
- **`swc-upload-attachment type="card"`**: file-style card attachments (one or more)
- **`swc-upload-attachment type="media"`**: media tile attachments (one or more, with or without badge)

**Use one layout type per composer session** (`card` or `media`). Slot multiple attachments of that same type: for example, several cards or several media tiles. Do not mix `card` and `media` in the same strip; `swc-prompt-field` logs a development warning when both are detected.

This rule is about **component layout**, not file MIME type. You can attach many files in one session as long as they share the same layout:

- **Document-only uploads** where title and subtitle carry meaning → all **`type="card"`**
- **Visual previews** (photos, storyboard frames) → all **`type="media"`**
- **Mixed images and documents in one batch** → normalize to all **`type="media"`**: image previews in `thumbnail`, and document tiles with a preview or icon in `thumbnail` plus an optional **`badge`** (for example, "PDF"). See **[Media with badge](/docs/patterns-ai-toolkit-upload-attachment--docs#media-with-badge)**.

**Populate the attachment strip** by slotting **one `<swc-upload-attachment>` per file**, each with **`slot="attachment"`** (same slot name repeated).

For additional card and media gallery examples, see **[Multi-card](/docs/patterns-ai-toolkit-upload-attachment--docs#multi-card)** and **[Multi-media](/docs/patterns-ai-toolkit-upload-attachment--docs#multi-media)**.

Upload button behavior:

- Emits cancelable **`swc-prompt-field-upload-click`**; consumers own picker behavior
- Consumers provide attachments by slotting; file selection stays in app code

Attachments own dismiss behavior via **`dismissible`** and emit **`swc-upload-attachment-dismiss`**.

### Multi-attachment scroll

When the attachments don't fit, the strip scrolls horizontally. This works the same for `type="card"` and `type="media"` tiles.

- Round chevron buttons show on each side when there is more content in that direction. `>` moves the tile that is partly hidden at the end to the start of the strip; `<` does the reverse.
- Edge fades show that more content is off screen. The fades and chevrons come in as soon as the strip scrolls.
- Users can also scroll with a trackpad, mouse wheel, or touch. The strip has no visible scrollbar and doesn't snap to tile edges.

<Canvas of={PromptFieldStories.MultiAttachmentScroll} />

### Upload action menu

`swc-prompt-field` fires `swc-prompt-field-upload-click` from the **`+`** button. The consuming product decides what opens. Design recommends a menu with at least:

- **Add from Adobe cloud storage**
- **Attach files**

Products can add more sources. Show files from every source as `swc-upload-attachment` tiles, with the same error/invalid state as a dropped file.

## States

- **Default**: send button shown, normal interactivity; enabled once there's prompt content (value or attachment)
- **`generating`**: stop button shown in place of send while a response is in progress; the input remains editable
- **`disabled`**: input, upload, and send/stop are all disabled

## Behaviors

### Handling events

Prompt field uses an uncontrolled-with-mirror event model:

- **`swc-prompt-field-input`** fires after the internal textarea value updates
- **`swc-prompt-field-submit`** carries the current `detail.value`
- **`swc-prompt-field-upload-click`** is a cancelable trigger for external picker flows

Consumers are responsible for handling upload flows and can mirror `value` from events when needed.

<Canvas of={PromptFieldStories.HandlingEvents} />

### Animate loader

The status loader stays static by default. Set `animate-loader` to animate it while `generating` is set; the loader returns to static once generation ends.

<Canvas of={PromptFieldStories.AnimateLoader} />

### Drag and drop

Dragging a file over `swc-prompt-field` shows a solid fill and a blue focus ring, for every `variant` and also while `generating`. Text and URL drags are rejected, and so are all drags on a `disabled` field. Dropping fires **`swc-prompt-field-drop`** with `detail: { files: File[] }`. Build and slot `<swc-upload-attachment>` elements from those files, the same as for the **`+`** button's picker flow.

When the new tiles land in the `attachment` slot, the first new tile becomes the strip's Tab entry point. If the textarea had focus at drop time, focus stays there. Otherwise, focus moves to the new tile only during keyboard use (`:focus-visible`); after a mouse drag, focus stays where it was.

## Accessibility

### Features

The `<swc-prompt-field>` element implements the following accessibility features:

#### Label association

- The `<textarea>` uses `aria-labelledby`, pointing to a visually hidden label
- `accessible-label` can override the accessible name when needed
- All icon buttons carry descriptive accessible names via `accessible-label`
- `attachment-scroll-prev-label` and `attachment-scroll-next-label` let consumers localize the attachment-strip chevrons
- The send button uses `disabled` natively when the prompt has no content

#### Attachment strip keyboard navigation

The attachment strip is a `role="region"` landmark (labeled by `attachment-strip-label`, default "Uploaded assets strip") that contains roving-tabindex thumbnails. The landmark itself is not a tab stop.

- **Tab**: moves to the previous chevron (when shown), the active thumbnail (the first one until the arrow keys move it), that thumbnail's Close button, the next chevron (when shown), and then out of the strip
- **Arrow Left/Right**: move to the previous or next thumbnail and scroll it into view
- **Shift+Tab** from a Close button returns to its thumbnail; **Shift+Tab** from a thumbnail leaves the strip
- Activating a chevron (click, Enter, or Space) scrolls the strip and keeps focus on the chevron. **Shift+Tab** from `>`, or **Tab** from `<`, moves into the tiles that are now shown
- At the end of the strip, the chevron for that direction is hidden. If it had focus, focus moves to the thumbnail at that end: the last one for `>`, the first one for `<`

### Best practices

- Always provide a meaningful `label` value
- Use `accessible-label` only when a distinct non-visual name is required
- Use `placeholder` as a hint, not a replacement for the label
- Ensure attachment content slotted into `attachment` slot includes descriptive text
- Give every `swc-upload-attachment` a `title` slot (for example, the file name) or an `accessible-label`. This includes `type="media"` tiles, which don't show the title. Screen readers use it as the tile's name
- Keep the **`+`** button available: drag and drop has no keyboard equivalent, so keyboard and screen reader users attach files with the button
